# RumaQ — REST API Contract

Base URL: `https://rumaq.ahaqqu.com/api`

All paths are relative to this base. The Worker mounts routes under `/api/*`.
Protected endpoints require the `rumaq_session` cookie. Responses are JSON.
Errors use `{ "error": "..." }`.

> This file is generated by `./scripts/docs.sh`. Do not edit manually.

## Caching

- **Public GET endpoints** (`/health`, `/auth/email-status`): `Cache-Control: public, max-age=60`.
- **Authenticated GET endpoints** (`/me`, `/stock`): `Cache-Control: private, no-cache` — never cached at the edge.
- **Error responses**: `Cache-Control: private, no-cache`.

| POST   | /api/tasks                                                 | Yes  | —                                                                | `{ title, assignee_member_id, due_date, recurrence }`                                             | Creates a task: free-text title (trimmed, 1-120 chars — no preset categories, the #422 philosophy), optional assignee (ANY household member — linked or profile-only, 0021), optional due date and recurrence. Any linked member can create; profile-only members never act (no account, 0021). needs_approval derives server-side: true when the assignee is a profile-only member. The create audit record commits in the same batch.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| DELETE | /api/tasks/{id}                                            | Yes  | `id`                                                             | —                                                                                                 | Hard-deletes a task: creator or household owner. The deletion audit record commits in the SAME batch as the delete and survives it (household_task_audit.task_id is a plain TEXT handle — no FK), so the household’s completion history outlives the row.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| PATCH  | /api/tasks/{id}                                            | Yes  | `id`                                                             | `{ title, due_date, recurrence, assignee_member_id, status, approve }`                            | One endpoint, three actions. (1) Edit fields — title, due_date, recurrence, assignee_member_id (assign/reassign, null unassigns): creator or household owner; reassignment re-derives needs_approval from the new assignee’s mode and clears any prior approval; an empty patch is a no-op read. (2) Complete — status:"done" alone: the assignee (when linked), the creator, or an owner; profile-only assignees are completed on their behalf; a one-shot task flips to done, a RECURRING task rolls its due date to the next occurrence and stays open. (3) Approve — approve:true alone: creator or owner, only while needs_approval and the task is done; sets approved_by_member_id.
